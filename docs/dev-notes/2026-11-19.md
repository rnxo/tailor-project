## ReactNativeとWebでのスタイル指定の違い

**Web(特に自分)**: 素のCSSでスタイルを指定しない。主に**tailwindCSS**を使用している

**ReactNative**: StyleSheetというオブジェクトによってスタイルを指定する

Reactの場合

```tsx
const styles = {
  title: { fontSize: 20, fontWeight: 'bold' },
};
<h1 style={styles.title}>Title</h1>
```

のようにReactNativeのStyleSheetの似ている -> そもそも**ReactNative**はWeb開発のような開発体験をネイティブアプリで可能にするためMeta社が開発したフレームワークなので、似ているのも同然である。

Tailor のいまのコードでは、この問題はほぼ起きません。FlatList が renderItem に渡す article は、useState に入っている配列の要素そのものです。描画のたびに新しく作られるわけではありません。また、このプロジェクトでは React Compiler が有効です（app.json の reactCompiler: true）。React Compiler は自動でメモ化をしてくれます。

### そもそもなんでプリミティブで渡した方がいいのか

参照: [vercel-react-native-skills](https://github.com/vercel-labs/agent-skills/blob/main/skills/react-native-skills/rules/list-performance-item-memo.md)

**React Compiler**が**Object.is**による浅い比較をするのが根本的な原因である。

primitive value -> "Taro" === "Taro"のように**memo()** は「変化なし」と判定
object -> 参照つまりメモリ上でどのオブジェクトなのかを比較する。だから中身が同じでも参照先が一致しない場合**memo()** は「変化あり」と判定し再レンダリングするからオブジェクトではなくプリミティブな値としてpropsを渡すことがベストプラクティクス
### **FlatList**コンポーネントってなに？

ReactNativeでスクロールビューを宣言するためのコアコンポーネントである**ScrollView**の問題を仮想化という仕組みで解決するためにReactNativeのコアコンポーネントである。

解決する問題
-> **ScrollView**は中身にある全要素をレンダリングし、画面外にいってもすべて保有するという特徴をもっている。そのためメモリ消費が増え、端末の操作が重くなる
こちらの問題を仮想化によって
`画面の上下10個分 + 画面に収まる要素`のようにレンダリングをし、こちらの範囲をこえた要素は破棄され端末のメモリ消費を抑える

### **FlatList**のrenderItemってなに？

**FlatList**が画面に描画する要素（コンポーネント）を返す関数を渡すためのプロパティ
描画するデータは`data`プロパティに渡す

### なぜTanstack Queryを使った再取得のときに問題が起きるのか

**Tanstack Query**、**ReactNative**、Vercel社が提供している**react-native-agents-skils**を見ると、
claudeが間違っていた。

問題なしな理由
> **useQuery()** にはデータの再取得のときに前回のデータ一致するのかを判定します。そして一致した場合には、そのまま前回のデータを使用するため**Object.is**は参照が一致すると判定をして再レンダリングが起きない
